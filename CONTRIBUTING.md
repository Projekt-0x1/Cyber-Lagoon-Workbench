# Contributing mechanisms

This is a mechanism workshop. A contribution is strongest when it removes or replaces machinery while preserving or improving a falsifiable Adult phenotype.

## Before implementation

For a substantive cognition, learning, language, social, planning, memory, affect, perception, or action mechanism, write the causal hypothesis before choosing the architecture.

Your issue/PR must contain:

1. **Functional problem.** What measurable Adult behavior or update law is missing, wrong, too expensive, or over-authored?
2. **Incumbent and challenger.** Name the current mechanism, the smallest challenger, and the deletion/replacement criterion.
3. **Mechanism-specific grounding.** Cite primary evidence and at least one independent/review source for the exact functional problem. Separate literature findings from your engineering inference.
4. **Sapolsky destructive audit.** Hold current contact fixed and vary at least one relevant prior cause: development, recent history, source/social history, body/resource state, controllability/predictability, delayed consequence, or recovery. State what should break, reverse, delay, redirect, or recover.
5. **Chomsky structure-dependence audit.** For substantive language/cognition semantics, predeclare a held-out structural falsifier involving composition, hierarchy, recursion, long-distance dependence, or structure-sensitive ambiguity. Linear wording similarity is not enough.
6. **Tony Robbins audit.** Record whether state/focus/reframing/physiology claims contribute a testable causal constraint. `NO_RELEVANT_CONTRIBUTION` is a valid result. Motivational vocabulary is never evidence or an architecture authority.
7. **Authority boundary.** State exactly who can select current thought, meaning, evidence, participation, credit, action, and world truth. A public/host contribution interface must not acquire those authorities.
8. **Novel-synthesis boundary.** If the exact mechanism is novel, say `NOVEL ENGINEERING SYNTHESIS`; ground its constituent functions and attack it with stronger counterfactuals instead of inventing biological precedent.
9. **Resource envelope.** State persistent bytes, hot working set, touched work, latency, and failure behavior when relevant to the change.

## Implement at the cheapest rung

Use the first rung that can falsify the hypothesis:

```text
focused reference mechanism/falsifier
        ↓
bounded canonical program/state data
        ↓
already-built Direct evaluator
        ↓
retained Direct Adult checkpoint branch
        ↓
full physical qualification
```

Do not start with a new CUDA kernel if an existing generic executor can express the change as data. Rebuild the Direct engine only when a genuinely general executor/ABI primitive must change.

`./bench` is the inner loop and intentionally has no build path.

For the current compile-free Direct lane, edit `experiments/current_recipe.ir`. Its present operation vocabulary is deliberately narrow. Do not represent an unsupported cognitive law by smuggling semantic labels into its numeric fields.

## Two semantic lanes

### New organism mechanism

A new cognitive/learning law must be content-free mechanism law or be acquired/revised by resident experience. Host code cannot hot-inject a current semantic policy into an already-living Adult.

Required evidence normally includes the focused reference falsifier, matched-history controls, lesion/withdrawal, exact checkpoint/replay, resource refusal, and the relevant transfer/structure-dependence test.

### Representation/execution change

A representation-only or execution-only challenger may use the engineering equivalence lane. It must preserve declared future behavior **and future update authority**, then prove a measurable economic win. Only a proof-gated quiescent backing replacement may cross into the existing Adult; the engineering receipt remains semantically powerless.

## Direct experiments

Compile-once Resident Recipe IR:

```bash
./bench --no-reference --ir experiments/current_recipe.ir
```

Retained real Direct Adult, disposable checkpoint branch:

```bash
./bench --contact path/to/raw-contact.bin
```

A passing rapid experiment is still `experiment_only`. Do not relabel it production GREEN.

## PR evidence

Include exact commands and compact receipts for:

- focused reference falsifier;
- compile-free Direct run when the current IR can express the mechanism;
- retained Direct Adult branch when relevant;
- incumbent/challenger state/work/latency comparison;
- lesion/withdrawal/matched-history controls;
- Chomsky structural falsifier for semantic language/cognition changes;
- checkpoint/replay and resource boundary where future-causal state changes;
- remaining RED and the next falsifier.

Do not paste giant logs. Commit bounded receipts or summarize exact measurements with enough provenance to rerun them.

## Architecture is replaceable

Network, Occurrence, Recipe, relation solver, language organization, CUDA graph, and current reference classes are hypotheses, not sacred ontology. Port before replace: preserve the donor phenotype and future update authority under matched interventions, then delete the inferior representation when the challenger wins.

A feature-specific module that merely manufactures the desired answer is not an acceptable replacement.
