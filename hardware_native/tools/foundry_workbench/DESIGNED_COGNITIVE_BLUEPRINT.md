# Designed Cognitive Blueprint

This is the single shared design document for the graph-neutral language workbench.
The architecture is a hypothesis. The loop is:

> assemble the causal vehicle deliberately, run it, inspect failure modes, repair the
> mechanism, and rerun.

Learning is machinery in the assembled vehicle. It is not a substitute for authoring
attention, memory, planning, language, monitoring, causal credit, structural revision,
constructor loops, and resource behavior.

## Mathematical-network north star

The intended Adult is a continuing mathematical network organism. Its durable
causal substrate is recruited, weighted, delayed, resource-constrained topology;
Occurrences are transient activations and exact causal witnesses in that topology.
A Recipe is one possible compact executable closure over a repeatedly useful Network.
It is not the organism's basic ontology and must not replace network formation,
competition, recurrence, plasticity, or structural revision.

The Foundry must therefore support all three forms without privileging today's structs:

1. explicit sparse Network topology and its live Occurrences;
2. candidate closures induced from repeated Network dynamics;
3. condensed Recipes whose equivalence and resource advantage are measured, and
   which can deoptimize back into witnessed topology.

No design wins because it is called a Network or Recipe. It wins only if the same
causal controls show better transfer, revision, capacity, and work on held-out contact.
Thousands of feature-specific Recipes, one Python module per cognitive skill, and
language-only executor branches are architectural drift signals.

## Evidence boundary

The bench contains no attached Adult. Humans and LLM workers may design its initial
causal machinery offline, but runtime receives only a frozen numeric state and
authenticated numeric contacts. Runtime has no prompt, semantic summary, model call,
network access, compiler, CUDA, or host API for choosing the current thought.

A GREEN reference receipt demonstrates only that the declared logical mechanism
survived its controls. It does not establish Adult language, acquisition, understanding,
human-level composition, production parity, or a constitutional graph transition.

Required receipt fields:

```text
reference_only=true
adult_attached=false
offline_authored_starting_state=true
experimental_ir=ReferenceRecipeIrV1
opaque_relation_ir=OpaqueRelationStateV2.experimental
production_ir=ResidentRecipeIrProgram.vcurrent
translation_status=UNDEFINED
physical_direct_parity=NOT_RUN/RED
graph_flip=false
```

## Two authoring planes

### Plane A: species and development

`DirectGenomeV1` in
`hardware_native/src/hardware_native/direct_network_genome.cuh` is the canonical
species/development blueprint for the current production tree:

- `DirectGenomeHeaderV1`
- `DirectTerritorySpecV1[]`
- `DirectFieldSpecV1[]`
- `DirectRuleSpecV1[]`

It is content-addressed and lowered by `lower_direct_genome_v1`. It authors
developmental causes, not mature wires, current thoughts, language content, answers,
or semantic routes. `recipe::Genome/GammaV1` is a retained lowering ABI, not
authoring authority. `G1SealedBlueprint` and `G1BlueprintBuilder` are retired donor
designs and must not be revived.

This authority describes what the repository currently executes; it is not a promise
that DirectGenomeV1 is the final representation. A replacement may change fields,
rules, lowering, or topology if it preserves the causal evidence boundary and wins an
exact differential experiment.

### Plane B: cognition

Current cognition belongs in bounded, versioned Network/Occurrence/Recipe IR executed
as data by one stable generic executor. Networks own distributed state and interaction;
Occurrences own transient participation and ancestry; Recipes are optional reusable
causal transformations, not compiled kernels, words, sentences, tests, or thoughts.

The experimental `ReferenceRecipeIrV1` is not claimed to be production
`ResidentRecipeIrProgram.vcurrent`. Their translation remains undefined until a later
differential parity effort proves exact transition equivalence.

## Organism law

The workbench constructs a continuing organism, not a prompt/response service. Language is one endogenous action ecology inside an always-continuing causal subject. A valid reference organism can receive contact, continue without contact, preserve unresolved alternatives, reinstate memory, plan, ask, wait, speak, monitor and revise its own expression, settle consequences, learn, and later behave differently. A one-shot query-to-surface assay is only a probe into that organism and must never become the runtime architecture. Host code may transport contact and explicit experimental interventions; it may not inject the current goal or choose the current thought.

## Quantified population law

Quantity is a first-class causal variable. Every scale receipt must report exact counts for persistent plastic matter, resident relation incidence, simultaneous Occurrences, active Network participation, eligibility, independently updateable plastic sites, unresolved alternatives, recurrent horizon, connector width, field/receptor sites, constructor reserve, and public trajectory extent. Cold address space and unused IDs do not count. A unit counts only if it has real stored or lawfully generated state, can participate or update independently, costs resources when touched, and scale or lesion changes behavior or learning. Tensor-core, sparse/frontier, RT/BVH and state-space lowerings may make these exact populations feasible on consumer hardware but never supply cognitive authority.

## Starting causal state

The offline author supplies a bounded snapshot of candidate internal causal state:

- current Occurrences and exact bindings;
- current Network closure and unresolved alternatives;
- chronology, source, route incarnation, and provenance class;
- resident Recipe identities and revisions;
- resource pressure, work limits, and expiry;
- live consequence tickets and eligibility;
- constructor/condensation witnesses;
- complete trace and checkpoint state.

The snapshot is not a user prompt or semantic summary. Literal strings, expected
answers, semantic domains, motor routes, surface payloads, bind/emit directives,
language labels, and host-created goals are forbidden anywhere in Recipe IR.

`interchange.py` is the sole scenario transport. Its document has only a version and
bounded numeric steps. It may introduce authenticated contact or explicit experimental
interventions, but cannot declare Recipes, select a resident alternative, publish
expected output, or write surface bytes.

`starting_state_verify.py` proves the intended fast workflow directly: construct a
complete learned numeric state offline, freeze and hash it, supply only authenticated
query-shaped input, and inspect the executor's resulting byte trajectory. Exact replay,
altered input, opaque identity permutation, duplicate identity, unknown field, stale
identity cursor, and literal-state tampering are mandatory controls.

`starting_state_freezer.py` is the authoring boundary used by external workers. It
accepts exactly one complete `ReferenceStateV1` body, supplies the fixed verified pool
root itself, validates the reconstructed machine, requires canonical reserialization,
and emits a checkpoint plus a surface-free hash/count manifest. It cannot accept Recipe
declarations, prompts, expected output, or partial host commands. `interchange.py`
subsequently consumes that frozen checkpoint in a separate execution step.

## Resident tick law

One deterministic tick follows this order:

1. Authenticate and settle the exact pending consequence before cognition.
2. Validate ticket, runtime incarnation, deadline, channel, and source.
3. Admit current authenticated contact atomically or refuse without mutation.
4. Recompute current closure, guards, ambiguity, provenance, and resources.
5. Refuse on zero, multiple equal, stale, unaffordable, or incomplete candidates.
6. Execute one current reusable Recipe Occurrence.
7. Publish one compact Occurrence and its byte trajectory.
8. Record exact constituent-root and per-byte ancestry.
9. Freeze action contributors and open bounded consequence eligibility.
10. Checkpoint complete state, work, trace, tickets, resources, and provenance.

With a pending action and no authenticated return, zero-input continuation refuses.
The host cannot enqueue a goal, arbitrate candidates, verify the current thought, or
turn independence alone into positive credit. Positive credit requires a measured
causal difference relative to the resident counterfactual.

## Resource and structural law

All queues, programs, payloads, contacts, provenance, traces, mutations, alternatives,
actions, checkpoints, and per-tick work have fixed bounds. Overflow or exhaustion
refuses atomically.

Recurring expensive Networks may condense into a `p(n+1)` Recipe only with a complete
constituent witness, held-out equivalence, and measured resource benefit.
Contradiction, withdrawal, or lesion can deoptimize and rematerialize the witnessed
lower structure. Condensation must reduce work, not strand thousands of near-duplicate
Recipes.

Every active Recipe must have a causal role, owning Network, state ABI, resource
envelope, falsifiers, and a reachable consumer. Verified-but-unused candidates remain
outside resident state.

Eligibility, causal credit, recursive condensation and silicon quantity follow
sections 3--6, 13 and 17 of the canonical learning ecology. The workbench tests those
laws; it does not maintain a second architecture. Its Network-versus-Recipe comparison
must include settlement locality, eligibility bytes, decay work, overlapping-route
attribution, source-withdrawal repair and credit equivalence across condensation and
rematerialization.

## Network-versus-Recipe decision experiment

The next fast Foundry comparison uses one frozen numeric contact history and one set
of falsifiers against three executors: explicit sparse Network, induced closure, and
condensed Recipe. The condition label exists only in the evaluator.

Each executor must face opaque identity permutation, held-out relation recombination,
opposite authenticated consequence, equal ambiguity, structural lesion versus remote
sham, source withdrawal and reacquisition, altered-current divergence, exact
checkpoint/replay, and one-less-than-required resource refusal. Receipts report active
nodes, edges, Occurrences, touched incidence, bytes of hot state, work per tick,
revision locality, recovery cost, and retained causal ancestry.

The Network representation is preferred when it learns or revises with less authored
structure or avoids stranded closures. A Recipe is admitted only when it preserves
held-out behavior and ancestry while measurably reducing hot work or state. If neither
wins, repair recruitment, plasticity, indexing, or the executor rather than adding a
feature-specific module.

Reference success is mechanism evidence until the same law is reachable from ordinary
birth, step, settlement, and checkpoint production lineage. A header plus a CUDA
contract is not capability GREEN when the continuing Adult never calls it. Graph work
must distinguish `reference_mechanism`, `production_reachable`, and
`behaviorally_proved` instead of collapsing them into one status.

Every Foundry mechanism has a conversion budget: map it to one graph-owned invariant,
falsify it quickly, then either lower the smallest general primitive into the ordinary
Adult path or retire the experiment. Foundry file count and scenario count are not
progress measures. Semantic fixture APIs, literal templates, and evaluator-selected
partitions never cross the donor boundary.

## Reference compositional scenario

`reference_contract_1610.py` contains six generic numeric Recipes and one continuing
reference state. It covers:

- grounded multilingual contact and held-out relational recombination;
- agreement, coordination, and coordination permutation;
- depth-2 and depth-3 recursive multi-clause reuse;
- one executable compact Occurrence;
- complete frontier, constituent-root, and per-byte ancestry;
- no-teach, omitted-constituent, ambiguity, mismatch, and resource refusal;
- source withdrawal, cascading provenance, and reacquisition;
- focal versus matched-remote lesion;
- condensation, deoptimization, and rematerialization;
- exact checkpoint/replay and corrupt-checkpoint refusal;
- opaque ID/slot/ticket permutation invariance;
- stale, wrong-ticket, wrong-incarnation, wrong-channel, and wrong-source returns;
- altered-input divergence and literal-bypass refusal;
- causal-difference credit and proof that independence alone gives no credit.

The authoritative entry point is `run_reference_contract_1610.sh`. The retained
`run_foundry_workbench.sh` adds only DirectGenome and Life-Function reference guards.
Both are hard-bounded to 60 seconds and remain CPU-only.

`OpaqueRelationStateV2.experimental` adds a stricter graph-neutral assay: authenticated
chronological prior/later Occurrences recruit an opaque relation hypothesis but emit
nothing on ingestion; a later resident current occurrence may create a clearly marked
provisional action; only its independently authenticated causal difference revises the
closure's credit. It covers network-local sparse incidence, causal ambiguity,
per-byte ancestry, withdrawal lineage, capability-split checkpoint custody, action
isolation, and observer-snapshot isolation. Its current Recipe-keyed scalar credit is
deliberately a falsifiable reference simplification and does not satisfy the
edge-local eligibility law above. Its full observer snapshot is also an explicit
reference-only scaling ceiling, not the intended telemetry interface. Its receipt explicitly excludes
consequence-earned initial learning, consumer scale, production parity, and Adult or
language capability.

## Retirement decision

The symbolic `foundry.py`, `reference_vm.py`, `full_loop.py`, compatibility
aliases, authored symbolic organisms, architecture packs, and their transitive tests
were deleted as one closed legacy dependency family. They permitted semantic
`domain/channel/emit` structure, caller-shaped pass judgments, or incomplete
consequence authority. They are not retained as a donor or fallback.

Useful ideas return only by being re-expressed in the bounded numeric IR and surviving
the same hostile controls. No compatibility requirement can weaken this boundary.
