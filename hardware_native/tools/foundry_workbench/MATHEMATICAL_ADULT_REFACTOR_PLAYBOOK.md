# Cyber Lagoon — Mathematical AGI refactor playbook

Status: required Workbench migration doctrine for substantial AGI refactor/cognition work.

## 1. Mission

Refactor the existing Adult **in place** toward the mathematical-organism architecture. Do not create a parallel mind, compatibility museum or second runtime.

Working semantic identity:

```text
(z_(t+1), o_t) = Phi_G(z_t, u_t)
```

`G` is content-free species/mechanism law. `z_t` is the continuing individual's heterogeneous future-causally-sufficient mathematical state. `u_t` is authenticated contact. `o_t` is outward action.

`z_t` is not one giant vector, permanent graph, tissue ontology or CA lattice. Recipes, Occurrences, Networks and causal programs are current donor/winning representations of useful causal roles, not mandatory primitives. Their functions survive until a measured challenger replaces them; their concrete storage/execution forms do not.

## 2. Product pressure

Language mastery is priority #1 because fluent continuing conversation forces memory, prediction, uncertainty, source history, reference/common ground, social contingency, repair, initiative, inhibition/silence, planning and online learning to integrate in one organism.

The near-term target is a Living Adult that can be resumed through a terminal / Claude Code / Codex body surface and interacted with naturally while remaining one continuing learned individual.

## 3. Existing-files-first migration

Default procedure:

```text
find current causal owner
-> state the protected organism function
-> separate function from representation
-> express the function as compact mathematics/state transition
-> edit the existing owner/callers
-> delete superseded representation
-> run fast hostile assays
-> climb physical parity only when justified
```

Do not default to `*_v2`, duplicate Recipe/Network stacks, permanent adapters or semantic sidecars.

## 4. LLM cognition emulator lane

A frontier LLM may explicitly imitate cognition inside the Workbench before AGI can do it itself.

This is allowed to be deep. The scaffold may prototype:

- current thought trajectory;
- alternatives/uncertainty;
- question formation;
- clarification/repair;
- plans and decompositions;
- discourse behavior;
- candidate intermediate relations/state variables;
- action policy.

Purpose:

```text
candidate cognitive function
-> LLM SCAFFOLD/ORACLE imitates target cognition
-> observe behavior + useful intermediate structure
-> derive mathematical mechanism hypotheses
-> build resident challenger
-> compare / lesion / substitute
-> remove scaffold
-> AGI retains behavior itself or hypothesis fails
```

Rules:

- Label the lane `SCAFFOLD/ORACLE`.
- Scaffold-dependent behavior is never AGI capability evidence.
- LLM hidden state/context is never silently AGI resident state.
- LLM answers/labels do not become production semantic authority.
- Record exactly what the scaffold contributed.
- Prefer progressive substitution: replace more and more of the scaffold with resident mathematics.
- Promotion requires the LLM scaffold absent under held-out and causal controls.

The firewall is not "never imitate cognition with an LLM". The firewall is **never confuse prototype cognition with AGI cognition**.

## 5. Workbench ladder

Use the cheapest surface that can falsify the idea:

```text
R0 pure mathematical / reference assay
R1 coupled-mechanism assay
R2 subsystem / mathematical Adult simulation
R3 tiny production CUDA/device parity capsule
R4 full physical Adult build + GPU + sanitizer
R5 Life Function / developed-Adult tournament
```

Most cognitive invention belongs in R0-R2. Full Adult builds are still mandatory when generic production execution, checkpoint/state layout, causal phase ownership, Genome/Life Function physical path or real production integration changes.

The doctrine is not "never compile". It is "do not use the full Adult compile as the hypothesis-discovery loop".

## 6. Relation, solver and lowering are separate

Keep the source relation/operator semantics, the solver/execution strategy, and the physical hardware lowering independently replaceable:

```text
logical relation/operator semantics
              -> solver/execution strategy
              -> physical hardware lowering
```

A learned relation may be solved by closed form, projection, recurrence, fixed-point iteration, finite/discrete solving, causal-program execution, sparse algebra, tensor contraction or another earned strategy. That strategy may then lower to scalar/CUDA, Tensor Cores, state-space scans, integer/bit operations, BVH/RT traversal or future hardware. Replacing solver/lowering must not silently change learned causal state or intervention phenotype.

## 7. Timing is architectural

For every candidate measure before hardware optimization:

```text
active relation evaluations
active bindings
state touches
recurrence depth
branch count
materialized bytes
critical dependency depth
persistent state changed
```

Repeated local critical-path mechanisms should remain capable of microsecond-class physical execution where feasible. Deep cognition may legitimately take milliseconds/seconds by composing many cheap steps.

Presumptive RED signs: whole-Adult scans, whole-history scans, global traversals for local decisions, repeated large copies/allocations, per-Recipe compilation, work proportional to dormant state, or millisecond local primitives without measured capability gain.

**Assay-size law:** scale only the dimension whose scaling is part of the hypothesis. A state-equivalence or representation-deletion assay must not instantiate a huge dormant population merely because another scale contract does. Before shrinking a nuisance dimension, sweep a broad range and require the same positive phenotype, intervention trace and negative controls. Then keep a separate named large-scale control for the quantity actually under test. Fast gates should pay expensive scale once, not redundantly in every causal battery.

## 8. Quantity

Do not optimize for literal cell/neuron count. `80B` is a stress/reference profile, not the cognition metric.

Track useful causal quantity: active degrees of freedom, effective interactions, recurrent depth, live alternatives, future-relevant learned distinctions, composition depth, interacting timescales, cross-system coupling, touched work, persistent bytes, joules and latency.

## 9. Hot swap / state migration

"Hot swappable" means one of:

```text
same state semantics -> direct replacement
```

or

```text
old sufficient state -> explicit lawful transform -> new sufficient state
```

Never silently reset learned state. A representation migration must preserve continuing-subject identity and every future-relevant distinction protected by the capability contract.

**State-retirement law:** persistent state earns residency only while it can change a lawful future. Treat observer diagnostics, exactly reconstructable Species/default structure, exact duplicate evidence, and constructor/quorum variables whose transition has completed as deletion candidates. The proof boundary must be temporal: include a negative control immediately *before* the proposed retirement point showing that the coordinate is still causal there, then show it is unread/reconstructable and intervention-equivalent *after* the transition. Do not delete distinct episodes merely because they look repetitive; source, context, timing, withdrawal or boundary diversity may make them different future evidence. Canonicalize only distinctions proven equivalent.

## 10. Acceptance

Compare incumbent vs challenger on:

- public phenotype;
- held-out generalization;
- online learning/reversal;
- source/causal provenance;
- lesionability;
- persistent bytes;
- state touches / relation evaluations;
- latency;
- rematerialization;
- checkpoint/replay;
- amount of new substrate machinery required.

The long-term desired curve is capability accelerating while core substrate complexity flattens.

### Current reference anti-regression floor

Reference-only, not production claims or sacred architecture:

- continuing language Adult: `79 -> 159 -> 319` public bytes, depth `1 -> 2 -> 3`, eight distinct held-out clauses, decision width `1` under consequence/resource/social controls;
- operator-factorization scale: **64 distinct held-out clauses, depth 6, 2,495 public bytes, decision width 1**;
- recursive public representation: **zero persisted composite closures**;
- generic causal-program bank owns the opaque program->factor relation; the language Adult has no second `surface` shadow namespace;
- withdrawal, focal lesion, incremental reafference, local-learning and future-update-authority controls remain load-bearing.

Do not reset to an easier assay during refactoring. A challenger should improve this phenotype or preserve it while winning a declared state/work/latency/complexity target.

## 11. Visible-discourse and cumulative-capability commit gate

Every substantive change that alters AGI cognition semantics—state, learning, memory, composition, arbitration, execution, prediction, social inference, language or causal ownership—must contain a measured visible language/discussion improvement over the immediately preceding shared-main organism baseline. Only genuinely semantics-free documentation/tooling/compiler/hardware maintenance may preserve the complete phenotype instead, and then it must explicitly declare that boundary, win a predeclared measured state/work/latency/complexity target, and preserve future causal/update authority. A representation/state refactor inside AGI cognition is not exempt merely because its motivation is compression, simplification or speed.

The baseline is cumulative across mechanics. Shared `main` is one AGI/workbench lineage, not a set of owner-local feature islands. Every candidate must preserve every already-earned or concurrently-integrated affected capability. Any cognition-semantic change also adds its declared visible N+1 gain; only explicitly semantics-free maintenance may land on its declared economic gain alone. If long dialogue, inquiry, world-span discourse, prospection, source calibration or another peer capability turns RED after a representation change, the slice is RED until the union is restored. Never classify that regression as "peer-owned" or therefore ignorable.

Before commit, record a union receipt such as:

```text
new visible delta: terse failed clarification -> clearer learned rephrase
peer capability union: inquiry GREEN, long dialogue GREEN, world-span GREEN, prospection GREEN
```

The outward delta must arise through resident/shared mechanism state, not a host-selected answer or scripted expected string. Preserve the causal controls. Re-read current files immediately before finalizing because peers may improve the same operator while the assay is running.

### Continuous-life curriculum

Language development is one continuing causal life, not a sequence of host training jobs. Corpus contact is ordinary authenticated experience. New corpora, dialogue, questions, correction, world consequences, distractors, silence and later probes append to the same Adult chronology and may revise the same resident state. Never reset or rebirth merely to begin a new curriculum stage; never replace resident memory with a context window; never select a checkpoint after seeing later outcomes. Held-out means *not yet lived at that chronological point*. Repetition is another exposure, not a privileged optimizer step. The Adult may itself gate plasticity, retrieve without updating, rest, replay or consolidate; the prohibition is against an externally imposed train/inference phase split, not against resident multi-timescale learning control. Keep within-life online/continual learning separate from cross-life Genome/species engineering. See `docs/audits/2026-07-21-online-learning-cognition-red-team.md` OL1/OL2/OL6; Target-v5 language-ecology material is a historical donor where still useful.

## 12. Shared-main swarm

All frontier-model mechanics work directly in the same canonical shared `main` checkout/worktree. Alternate clones, worktrees or filesystem seats may assist with read-only inspection or compute, but they do not commit or push frontier `main`; changes are applied and validated in the canonical checkout.

- Re-read live files before editing and before finalizing.
- Inspect recent commits and current dirty paths.
- Preserve peer work.
- Resolve ordinary overlap/races yourselves using the live repo and tests.
- **Commit constantly** in small coherent exact-path commits.
- Never blanket-stage the shared tree.
- Push regularly from the canonical checkout. Fetch before push as a guard against accidental external publication.
- If canonical `main` is both ahead and behind `origin/main`, treat that as a synchronization fault: stop new frontier commits, preserve dirty work, merge published history, rerun affected union gates, then publish the unified line.
- Never force-push, rewrite shared history, hard-reset away peer changes, or rebase away a peer's published commits merely to remove ahead/behind status.
- Do not create private branches/worktrees merely to avoid collaboration or to publish competing `main` history.

Git commits in the canonical checkout are the swarm's synchronization/provenance/rollback mechanism; `origin/main` is its publication mirror, not an independent development line.
